# Инструкция для ИИ-агента: собрать приложение из этого архива

Задача — получить установочный пакет FORTIS Markdown Editor для той системы,
на которой вы сейчас работаете, и убедиться, что собранное действительно
запускается.

Собирать можно только под свою систему. С macOS не сделать Windows-установщик,
с Windows не сделать `.dmg` — для этого нужны Wine или Docker, и обходить это
не надо: проще собрать на нужной машине.

## Что получится

| Система | Файлы на выходе |
| --- | --- |
| macOS | `.dmg` и `.zip`, отдельно для Apple Silicon и для Intel |
| Windows | `Setup ....exe` — установщик, и второй `.exe` — переносимая версия |
| Linux | `.AppImage`, `.deb`, `.rpm` (x86-64 и arm64), `.tar.gz` |

## Шаг 0. Проверить, что есть всё нужное

```bash
node -v      # нужен 20 или новее
npm -v
```

Node.js нет — поставить с https://nodejs.org, вариант LTS, установщик по
умолчанию. На macOS подойдёт и `brew install node`.

Нужно около **2 ГБ** свободного места и работающий интернет: сборка скачивает
готовые бинарники Electron, примерно 100–300 МБ в зависимости от системы.
Дальше интернет не понадобится ни приложению, ни его пользователю.

## Шаг 1. Распаковать и войти в папку

```bash
unzip fortis-markdown-editor-сборка.zip
cd fortis-markdown-editor
```

## Шаг 2. Поставить зависимости

```bash
npm install
```

Занимает 1–3 минуты. В конце должно быть `found 0 vulnerabilities`.
Предупреждения `npm warn deprecated` — нормально, это про внутренние
зависимости сборщика, в приложение они не попадают.

## Шаг 3. Собрать

Выберите строку по своей системе:

```bash
npm run dist:mac      # macOS
npm run dist:win      # Windows
npm run dist:linux    # Linux
```

Первая сборка идёт 3–10 минут, дальше быстрее — скачанное кэшируется.

### Две особенности сборки Linux

**Обязательные поля пакета.** Сборка `.deb` и `.rpm` остановится с жалобой на
отсутствующие «project homepage» и «author email». Заранее их знать неоткуда,
заполняются одной командой:

```bash
npm run account -- любой-ник
```

Подставьте ник владельца на GitHub, если проект туда поедет, или любое слово,
если сборка нужна только для себя.

**Для `.rpm` нужен `rpmbuild`.** Без него сборка падает с сообщением
`Need executable 'rpmbuild' to convert dir to rpm`. Ставится так:

```bash
sudo apt install rpm        # Ubuntu, Debian
sudo dnf install rpm-build  # Fedora, RHEL
brew install rpm            # macOS, если собираете rpm оттуда
```

Ни то, ни другое не нужно, если вы собираете под macOS или Windows.

## Шаг 4. Забрать результат

Всё складывается в папку `dist/`:

```bash
ls -lh dist/
```

Файлы с `arm64` в названии — для Apple Silicon и для arm-процессоров;
без `arm64` — для обычных Intel и AMD.

Промежуточные папки `dist/mac`, `dist/mac-arm64`, `dist/linux-unpacked`
и `dist/win-unpacked` — это распакованное приложение до упаковки. Отдавать
пользователю нужно `.dmg`, `.exe`, `.AppImage` или `.deb`, а не их.

## Шаг 5. Убедиться, что собранное работает

Не ограничивайтесь тем, что команда сборки завершилась без ошибки — проверьте
запуск. Окна вы не видите, поэтому опрашивайте приложение через порт отладки.

Запустите собранное приложение в фоне, добавив ключ:

```bash
# macOS, пример для Intel-сборки
"dist/mac/FORTIS Markdown Editor.app/Contents/MacOS/FORTIS Markdown Editor" --remote-debugging-port=9333 &

# Linux
./dist/linux-unpacked/fortis-markdown-editor --remote-debugging-port=9333 &

# Windows
Start-Process "dist\win-unpacked\FORTIS Markdown Editor.exe" -ArgumentList "--remote-debugging-port=9333"
```

Через несколько секунд спросите список страниц:

```bash
curl -s http://127.0.0.1:9333/json/list
```

Должна быть цель с `"url": "fortis://app/index.html"`. Подключитесь к её
`webSocketDebuggerUrl` и вызовите `Runtime.evaluate`. Полностью рабочее
приложение отвечает так:

| Выражение | Ожидаемое |
| --- | --- |
| `location.origin` | `fortis://app` |
| `window.isSecureContext` | `true` |
| `typeof window.showDirectoryPicker` | `function` |
| `!!window.fortisDesktop` | `true` |
| `typeof window.katex` | `object` |
| `document.body.innerText` | непустой, начинается с `FORTIS` |

Страница распаковывается несколько секунд. Пустой `innerText` сразу после
запуска — не ошибка, подождите и спросите ещё раз.

Не забудьте закрыть приложение после проверки.

## Первый запуск у пользователя

Пакеты не подписаны сертификатом разработчика, и системы это заметят.
Предупредите об этом того, кому отдаёте сборку:

- **macOS** — «приложение повреждено или не может быть открыто». Лечится один
  раз: `xattr -dr com.apple.quarantine "/Applications/FORTIS Markdown Editor.app"`.
  Если файл принесли на флешке, а не скачали, окна обычно не будет вовсе.
- **Windows** — синее окно SmartScreen: «Подробнее» → «Выполнить в любом случае».
- **Linux** — `.AppImage` надо сделать исполняемым: `chmod +x`. Пакеты ставятся
  как `sudo apt install ./файл.deb` или `sudo dnf install ./файл.rpm`;
  неподписанный `.rpm` dnf поставит после подтверждения.

## Если не собирается или не запускается

| Что видно | Причина и что делать |
| --- | --- |
| `Please specify project homepage` | Только `.deb` и `.rpm`. Выполните `npm run account -- любой-ник` из шага 3. |
| `Need executable 'rpmbuild'` | Только `.rpm`. Поставьте `rpmbuild`, команда в шаге 3. |
| `bad CPU type in executable` | Запускаете сборку не под свой процессор. Сверьте `uname -m` с именем файла. |
| macOS: «приложение повреждено» | Не снят карантин, команда `xattr` выше. |
| `npm install` падает на скачивании | Нет интернета или он через прокси: `npm config get proxy`. |
| Сборка падает на нехватке места | Нужно около 2 ГБ. Освободите и повторите — скачанное не потеряется. |
| Окно открылось пустым и белым | Страница ещё распаковывается, подождите несколько секунд. |
| Linux: падает сразу после старта | Нет графического сеанса. Приложение само ищет запущенный X-сервер в `/tmp/.X11-unix`, но если его нет — поднимите свой: `xvfb-run -a ./fortis-markdown-editor`. |
| Linux: `GPU process isn't usable` | Не должно возникать: на машинах без `/dev/dri` приложение само отключает аппаратное ускорение. Если всё же возникло — запустите с ключом `--disable-gpu`. |
| Предупреждение про Content Security Policy | Не поломка. Показывается только при `npm start`, в собранном пакете его нет. |

## Чего не делать

- **Не пытайтесь собрать пакет для чужой системы.** Правьте не сборку, а место
  запуска: возьмите нужную машину.
- **Не открывайте `app/index.html` в браузере как замену приложению.** Так
  пропадут прямое сохранение в файл, экспорт в PDF одним шагом и постоянное
  хранилище.
- **Не правьте `app/index.html` руками** — это сборка, сделанная генератором.
  Исходник интерфейса и логики лежит в `src/`.
- **Не отдавайте пользователю содержимое `dist/mac` или `dist/win-unpacked`** —
  это промежуточные папки, отдавать надо готовые пакеты.

## Что где лежит

| Путь | Что это |
| --- | --- |
| `app/index.html` | Собранная страница редактора со всеми библиотеками внутри |
| `app/main.js` | Окно, меню, разрешения, экспорт в PDF |
| `app/preload.js` | Мост между окном и главным процессом |
| `src/` | Исходник прототипа — правки вносятся здесь |
| `docs/` | Описание прототипа и требования к функционалу |
| `build/` | Иконки: `.icns` для macOS, `.ico` для Windows, `.png` для Linux |
| `scripts/adhoc-sign.js` | Ad-hoc подпись macOS-сборки, запускается сам |
| `AGENTS.md` | Как установить уже готовый пакет |
