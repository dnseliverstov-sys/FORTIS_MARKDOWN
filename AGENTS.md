# Инструкция для ИИ-агента: установить и запустить FORTIS Markdown Editor

Этот файл написан для агента, который работает в терминале на чужой машине.
Задача читателя — довести приложение до запущенного окна и убедиться, что оно
действительно работает, а не просто «команда отработала без ошибки».

Если задача — не установить готовый пакет, а **собрать его из исходников**,
идите в [СБОРКА.md](СБОРКА.md): там подробный разбор именно сборки.

Человеку удобнее читать [README.md](README.md).

## Что это

Настольное приложение на Electron. Всё содержимое редактора лежит в одном файле
`app/index.html` — это собранная страница со встроенными библиотеками, интернет
ей не нужен. `app/main.js` — главный процесс Electron, `app/preload.js` — мост
между окном и главным процессом.

Приложение открывает окно с графическим интерфейсом. **Без графической сессии оно
не запустится**: на сервере без дисплея нужен Xvfb (см. раздел про Linux).

## Ветка 1. Есть готовый пакет

Если пользователю нужно просто пользоваться приложением, берите готовую сборку со
страницы `https://github.com/GITHUB_ACCOUNT/fortis-markdown-editor/releases`.
Сборка **не подписана** сертификатом разработчика, поэтому каждая система будет
сопротивляться — это ожидаемо, а не признак поломки.

### macOS

```bash
hdiutil attach "FORTIS Markdown Editor-1.0.0-arm64.dmg"
cp -R "/Volumes/FORTIS Markdown Editor/FORTIS Markdown Editor.app" /Applications/
hdiutil detach "/Volumes/FORTIS Markdown Editor"
xattr -dr com.apple.quarantine "/Applications/FORTIS Markdown Editor.app"
open -a "FORTIS Markdown Editor"
```

Файл с `arm64` в названии — для Apple Silicon, без него — для Intel. Проверить
процессор: `uname -m` (`arm64` или `x86_64`). Шаг `xattr` обязателен: без него
система скажет, что приложение повреждено.

### Windows

```powershell
Start-Process -Wait "FORTIS Markdown Editor Setup 1.0.0.exe"
```

Установщик покажет окно SmartScreen — «Подробнее» → «Выполнить в любом случае».
Есть и переносимая сборка (`...portable...exe`), она запускается без установки.

### Linux

```bash
chmod +x "FORTIS Markdown Editor-1.0.0.AppImage"
./"FORTIS Markdown Editor-1.0.0.AppImage"
```

Если система ругается на FUSE, добавьте `--appimage-extract-and-run`.
Пакеты для установки в систему:

```bash
sudo apt install ./fortis-markdown-editor_1.0.0_amd64.deb    # Ubuntu, Debian, Mint
sudo dnf install ./fortis-markdown-editor-1.0.0.x86_64.rpm   # Fedora, RHEL, CentOS
sudo zypper install ./fortis-markdown-editor-1.0.0.x86_64.rpm # openSUSE
```

После установки приложение появится в меню программ, запуск из терминала —
командой `fortis-markdown-editor`.

## Ветка 2. Запуск из исходников

Нужен Node.js 20 или новее (`node -v`).

```bash
npm install
npm start
```

`npm install` тянет бинарник Electron, около 100 МБ, — нужен интернет и пара
минут. Дальше интернет не нужен ни для запуска, ни для работы редактора.

`npm start` **не завершается**: он держит окно открытым, пока приложение
работает. Запускайте его фоновой задачей, иначе сессия зависнет на этой команде.

## Ветка 3. Собрать пакет

Собирать надо на той же системе, для которой делается пакет.

```bash
npm run dist:mac     # .dmg и .zip
npm run dist:win     # .exe
npm run dist:linux   # .AppImage, .deb, .tar.gz
```

Готовые файлы появятся в `dist/`. Перед первой сборкой `.deb` подставьте ник
владельца репозитория — иначе сборка остановится на отсутствующих метаданных:

```bash
npm run account -- мой-ник-на-github
```

Все три системы сразу собирает GitHub Actions: вкладка **Actions** → «Сборка
приложения» → **Run workflow**. То же самое происходит само при пуше тега `v*`.

## Как убедиться, что приложение действительно работает

Окна вы не видите, поэтому проверяйте через протокол отладки. Запустите
приложение с портом отладки в фоне:

```bash
npx electron . --remote-debugging-port=9333
```

Затем дождитесь появления страницы и опросите её:

```bash
curl -s http://127.0.0.1:9333/json/list
```

В ответе должна быть цель с `"url": "fortis://app/index.html"`. Дальше можно
подключиться к её `webSocketDebuggerUrl` и выполнить `Runtime.evaluate`.
Признаки полностью рабочего приложения:

| Что проверить | Ожидаемое значение |
| --- | --- |
| `location.origin` | `fortis://app` |
| `window.isSecureContext` | `true` |
| `typeof window.showDirectoryPicker` | `function` |
| `!!window.fortisDesktop` | `true` |
| `typeof window.katex` | `object` |
| `document.body.innerText` | непустой, начинается с `FORTIS` |

Собранная страница распаковывается несколько секунд. Если текст ещё пустой —
подождите и опросите ещё раз, это не ошибка.

## Чего не делать

- **Не открывайте `app/index.html` напрямую в браузере как «то же самое».** Тогда
  пропадут прямое сохранение в файл на всех системах кроме Chrome и Edge,
  однократный экспорт в PDF и постоянное хранилище приложения.
- **Не запускайте `npm start` в переднем плане**, если больше нечем прервать
  сессию: команда не возвращает управление.
- **Не пытайтесь собрать Windows-пакет на macOS и наоборот.** Нужен либо Docker
  и Wine, либо GitHub Actions.
- **Не считайте предупреждение Electron о Content Security Policy поломкой.** Оно
  показывается только при запуске из исходников и исчезает в собранном пакете.

## Если не запускается

| Симптом | Причина и что делать |
| --- | --- |
| `bad CPU type in executable` | Взят пакет не под тот процессор. Сверьте `uname -m` и имя файла. |
| macOS: «приложение повреждено» | Не снят карантин. Выполните команду `xattr` выше. |
| Linux: пустой экран или падение сразу после старта | Нет графического сеанса. Приложение само ищет запущенный X-сервер, но если его нет — поднимите свой: `xvfb-run -a`. |
| Linux: жалоба на пространства имён и песочницу | Запустите AppImage с `--appimage-extract-and-run`. |
| `npm install` падает на скачивании Electron | Нет доступа к интернету или он через прокси. Проверьте `npm config get proxy`. |
| Окно открылось, но пустое и белое | Страница ещё распаковывается. Подождите несколько секунд. |

## Где что лежит

| Путь | Что это |
| --- | --- |
| `app/index.html` | Собранная страница редактора со всеми библиотеками внутри |
| `app/main.js` | Окно, меню, разрешения, экспорт в PDF |
| `app/preload.js` | Мост между окном и главным процессом |
| `src/` | Исходник прототипа — правится здесь, а не в `app/index.html` |
| `docs/` | Описание прототипа и требования к функционалу |
| `scripts/make-icon.py` | Рисует иконки в `build/` |
| `scripts/set-account.js` | Подставляет ник GitHub в метаданные |
| `.github/workflows/build.yml` | Сборка под все три системы |
