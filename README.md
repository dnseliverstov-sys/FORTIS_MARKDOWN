# FORTIS Markdown Editor

Настольный markdown-редактор: работа с папкой как с рабочим пространством, вкладки,
визуальный режим и режим разметки, поиск по папке, сравнение файлов, история версий,
формулы, экспорт и импорт. Работает без интернета.

## Перед первой сборкой

Нужно только для Linux. Форматам `.deb` и `.rpm` обязателен адрес проекта, и без
него сборка останавливается. Поле `homepage` в `package.json` оставлено пустым —
это единственное место, где адрес указывается. Если проект лежит на GitHub,
вставьте туда ссылку на репозиторий:

```bash
npm run project -- https://адрес/проекта
```

Для macOS и Windows этот шаг пропускается.

## Запуск из исходников

Нужен [Node.js](https://nodejs.org) 20 или новее.

```bash
npm install
npm start
```

## Сборка установщиков

```bash
npm run dist:mac    # .dmg и .zip
npm run dist:win    # .exe (установщик и переносимый)
npm run dist:linux  # .AppImage, .deb, .rpm
```

Результат — в папке `dist/`. Каждую систему надо собирать на ней самой: Windows-пакет
с macOS не сделать без Wine, и наоборот. Linux-пакеты с macOS собираются, но для
`.rpm` дополнительно нужен `rpmbuild`.

Иконки рисуются скриптом (нужен Pillow: `pip3 install pillow`):

```bash
npm run icon
```

Он делает три файла: `icon.icns` для macOS — знак вписан с полями, как требуют
правила системы, иначе в доке он выглядит крупнее соседей; `icon.ico` для Windows
и `icon.png` для Linux — там знак занимает весь квадрат.

## Первый запуск у того, кому передали пакет

Приложение **не подписано** сертификатом разработчика — сертификат платный, а без
него каждая система встречает незнакомое приложение предупреждением. Это не
поломка сборки, но предупредить получателя стоит.

- **macOS** — «приложение повреждено или не может быть открыто». Снимается один раз:

  ```bash
  xattr -dr com.apple.quarantine "/Applications/FORTIS Markdown Editor.app"
  ```

  Метку карантина ставит скачивание из сети. Если файл принесли на флешке,
  окна чаще всего не будет вовсе.

- **Windows** — синее окно SmartScreen: «Подробнее» → «Выполнить в любом случае».

- **Linux** — `.AppImage` надо сделать исполняемым (`chmod +x`) и запустить.
  Пакеты ставятся обычным способом:

  ```bash
  sudo apt install ./fortis-markdown-editor_1.0.0_amd64.deb      # Ubuntu, Debian, Mint
  sudo dnf install ./fortis-markdown-editor-1.0.0.x86_64.rpm     # Fedora, RHEL, CentOS
  sudo zypper install ./fortis-markdown-editor-1.0.0.x86_64.rpm  # openSUSE
  ```

  Если система ругается на отсутствие FUSE, запустите `.AppImage` с ключом
  `--appimage-extract-and-run`. Файлы с `arm64` или `aarch64` в названии —
  для arm-процессоров.

## Что где лежит

| Путь | Что это |
| --- | --- |
| `app/index.html` | Само приложение — собранная страница редактора со всеми библиотеками внутри |
| `app/main.js` | Главный процесс Electron: окно, меню, разрешения, экспорт в PDF |
| `app/preload.js` | Мост между окном и главным процессом |
| `src/` | Исходник прототипа: разметка интерфейса и вся логика в одном файле |
| `docs/` | Описание прототипа и исходные требования к функционалу |
| `build/` | Иконки: `icon.icns` для macOS, `icon.ico` для Windows, `icon.png` для Linux |
| `scripts/make-icon.py` | Скрипт, который их рисует |
| `AGENTS.md` | Инструкция по установке готового пакета для ИИ-агента |
| `СБОРКА.md` | Инструкция по сборке для ИИ-агента |

## Чем настольная версия отличается от браузерной

- **Сохранение в файл без диалога.** `Ctrl+S` (на Mac `Cmd+S`) пишет прямо в открытый
  файл в любой системе. В браузере так умеют только Chrome и Edge, а Firefox и Safari
  скачивают копию.
- **Экспорт в PDF одним шагом.** Вместо системного диалога печати сразу открывается
  сохранение файла. Размер страницы, ориентация и поля берутся из настроек экспорта
  в самом редакторе.
- **Своё окно.** Размер и положение запоминаются между запусками, приложение живёт
  в доке и панели задач отдельно от браузера.

Данные редактора (открытая папка, вкладки, настройки, история версий) хранятся
в профиле приложения, а не в браузере, и не теряются при очистке истории.

## Горячие клавиши

На macOS вместо `Ctrl` — `Cmd`.

| | |
| --- | --- |
| `Ctrl+N` / `Ctrl+O` / `Ctrl+Shift+O` | новый файл, открыть файл, открыть папку |
| `Ctrl+S` / `Ctrl+Shift+S` | сохранить, сохранить как |
| `Ctrl+W` | закрыть вкладку |
| `Ctrl+F` / `Ctrl+Shift+F` | поиск и замена, поиск по папке |
| `Ctrl+E` / `Ctrl+Shift+E` | режим разметки, разделённый просмотр |
| `Ctrl+B` / `Ctrl+J` | дерево файлов, панель документа |
| `Ctrl+D` | сравнение файлов |
| `Ctrl+R` / `Ctrl+Shift+N` | недавние, шаблоны |
| `Ctrl+Shift+H` | снимок версии |
| `Ctrl+Shift+X` / `Ctrl+Shift+I` | экспорт, импорт |
| `Ctrl+Shift+P` | оформление |

Набор настраивается в самом редакторе.

## Ограничения

- Формулы в экспортированных HTML и PDF оформляются стилями KaTeX с внешнего CDN,
  поэтому без интернета такой документ покажет формулы неоформленными. В самом
  редакторе формулы работают офлайн.
- Не сделано: диаграммы Mermaid, Git, Confluence, живые данные Jira, экспорт в DOCX,
  локализация, плагины.

## Как это устроено

Окно грузится не с `file://`, а по собственной схеме `fortis://app`, объявленной
безопасной. Из-за этого работают `localStorage`, IndexedDB и File System Access API —
те самые, на которых держатся рабочее пространство, вкладки и прямое сохранение.

Экспорт в PDF редактор делает через скрытый `iframe` и `print()`. Настольная версия
перехватывает этот вызов в `app/preload.js` и отдаёт собранный документ главному
процессу, который печатает его в PDF и предлагает сохранить. Если перехват почему-то
не сработает, вызывается обычная печать — то же поведение, что в браузере.
